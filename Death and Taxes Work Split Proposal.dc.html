The two lanes

Each lane owns its own long-lived branch and its own folders in the project. A lane never edits the other lane's assets between gates — that is what keeps two people out of each other's .uasset files on Git.

Lane A
World

Vorgathul and Vaelmoor, level blockout, streaming, lore and naming content, the home hub.

Owns
  • Landscape, World Partition grid, streaming and HLOD
  • /Content/Maps, /Environment, POI and monument placement
  • Lore, naming tables, honor and title content
  • Loot, tome and resource spawn topology
Lane B
Systems

Mechanics and player interaction: combat, abilities, gear, UI, and the network layer under all of it.

Owns
  • C++ gameplay module: attributes, abilities, attack table, defense
  • Data assets, requirements, equip-gating, runes and sockets
  • Enhanced Input, camera, CommonUI screens
  • Replication, dedicated server, persistence — this lane owns netcode

Branch model

Git with LFS for binary content. Because .uasset and .umap cannot be merged, ownership is folder-level and absolute between gates.

Branch Life Rule
main Permanent Always compiles, always plays. Only gate merges and phase completions land here.
lane/world Long-lived Lane A only. Re-cut from main after every gate.
lane/systems Long-lived Lane B only. Same rule.
gate/<letter>-<name> Short Both lanes, together. Created at a halt, deleted after it merges to main and gets tagged.
  • LFS tracks *.uasset *.umap *.fbx *.wav *.png; Binaries/ Intermediate/ Saved/ DerivedDataCache/ stay ignored from commit one.
  • One owner per content folder. If both lanes need the same asset, that need is a gate, not a merge.
  • Shared C++ headers (tags, data-asset base classes) live in the gameplay module and only change on a gate branch.

Gate protocol

A gate is a point where the two lanes genuinely overlap. Rather than each dev guessing at the other's half, both stop, combine the branches, and build the overlap in one sitting.

01 Halt
Both lanes push what they have and take no new work.
02 Combine
Both lane branches merge into one gate/* branch.
03 Co-author
The shared artifact is built together, in one session, on that branch.
04 Land
Merge to main, tag it, write the decision down.
05 Resume
Lanes re-cut from main. What the gate settled is not reopened.
01

Foundation

Both devs, one branch

Empty Unreal project to a repository both devs can build and run. Nothing splits until this is done — every convention set here is one both lanes have to live inside.

  • Blank C++ project; one primary gameplay module plus an editor module; a dedicated server target added at commit one rather than retrofitted later
  • Git + LFS setup, .gitattributes / .gitignore, branch and tag naming, folder ownership map
  • Gameplay Tag registry seeded from the master doc taxonomy — Actor.* Stat.* Item.* State.* Trait.* Damage.* Effect.* — as config-sourced tags, no duplicates
  • Decision to make here: Gameplay Ability System as the base, or a custom C++ ability framework. Phases 3 and 4 are built on the answer.
Exit criteria

Both devs clone, compile, and run a client against a local dedicated-server build with a placeholder Zug'thar pawn. Tag registry compiles. One commit on main, ability framework chosen and written down.

02

Metrics & skeleton

The lanes split here. Both build the crudest possible version of their half so the numbers that bind them can be measured rather than argued.

Lane A — World
  • World Partition enabled, cell size and grid decided
  • Vorgathul interior blocked out at true scale — caves, vents, hub
  • A metrics rig level: door widths, step heights, ledge and gap tests
Lane B — Systems
  • Zug'thar pawn, Enhanced Input, camera rig
  • Movement tuning: walk, sprint, encumbered sprint, stamina drain
  • UAttributeComponent — 1–20 scale with growth-by-doing hooks firing off real actions
Gate A Movement metrics

Halt both lanes. Agree creature size, eye height, walk and sprint speeds, jump and fall tolerance, and the vent-launch arc. Bake the numbers into the base URaceDataAsset and the metrics rig in the same commit. Neither blockout nor movement tuning continues before this lands — every wall, doorway and encounter space built after it depends on these numbers.

03

Combat space

Combat gets its rhythm and the world gets its first surface zone. The overlap is physical: reach, flanking and ranged bands only work in space that was built for them.

Lane A — World
  • Landscape pass on the volcano exterior and the first surface zone
  • Geothermal vent launch volumes; POI graph and travel distances
  • Monument sites marked, with their recall-disabled volumes drawn
Lane B — Systems
  • Independent swing timers, 1.2–1.5s GCD, cast pushback
  • Single-roll attack table; Off-Guard from relative facing
  • Weapon traits — Agile, Reach, Forceful, Sweep, Deadly — as tag-driven modifiers
Gate B Encounter volumes

Halt both lanes and co-author three reference arenas in a shared test map — a corridor, an open field and a vertical space — sized against the real numbers: Reach collision boxes, the flanking arc that erases Dodge and Parry, and the 10m band where ranged threat changes. These arenas become the acceptance test for every later encounter space.

04

Data & content pipeline

Tomes, weapons and gear become data. This is where the weapon-defined class rule from the design doc gets implemented, and where the two lanes start editing the same kinds of files.

Lane A — World
  • Physical tome props and their world placement in ruins and dungeons
  • Loot and mob spawn topology, respawn timing per POI
  • Resource nodes — precious metals, extreme-environment herbs
Lane B — Systems
  • URaceDataAsset, UFeatDataAsset, UBookItemDataAsset, weapon and armor assets
  • FCharacterRequirement — tag query plus attribute minimums for legibility
  • Equip-gating: the weapon decides which learned abilities are usable, and re-weights the stats behind them
  • Rune and socket layer, transferable at a forge
Gate C Data ownership and the weapon-to-pillar map

Halt both lanes. Settle which weapons and weapon groups belong to Tank, Mage, Healer and Melee DPS — the open decision the design doc hands to this phase — and who authors which data asset, where the tables live, and how content edits avoid .uasset collisions. One naming and folder convention, checked in with the first real weapon and the first real tome.

05

Entry, extraction, rest

Both ends of the loop. Since extraction replaced the campfire, the hub is not decoration — it is where fatigue resets, stat points lock in and tomes are studied.

Lane A — World
  • Vent launch to airborne drop-in: the physical path out of the mountain
  • Home hub interior — rest space, clan hall, forge and market frontage
  • Landing-spread test: is the drop area readable from the air?
Lane B — Systems
  • Recall cast, uninterruptible but vulnerable; the longer group channel
  • Death and full loot: protected bag, weapon insurance, channeler inheritance
  • Extraction as the rest beat — fatigue reset, stat lock-in, tome study
  • Recall suppression inside the volumes Lane A drew
Gate D World state vs player state

Halt both lanes. Draw the line between what the world owns (spawns, respawn timers, vent state) and what the player carries home (attributes, grimoire, inventory, honor), and build the hub's rest interaction against it once. Everything in phases 7 and 8 reads from this boundary.

06

Raid & threat

The densest overlap in the project: an encounter is level design and systems design at the same time, and clearing it is only half the objective.

Lane A — World
  • First monument blocked out inside the persistent world, not an instance
  • Approach, chokepoints and the escape route you extract along
  • Ambush sightlines for the players who camp the exit
Lane B — Systems
  • Threat generated by abilities used, weighted by the equipped weapon
  • Mob AI and perception; aggro transition thresholds re-scoped
  • Encounter scripting hooks, conditions on the 2.0s DoT heartbeat, CC diminishing returns
Gate E One raid, co-authored

The longest halt in the plan. Both lanes stop and build the first monument end to end together — space, mobs, threat, loot and the extraction that follows the kill. It sets the template every later raid is authored against, and it is where PvP-invasion risk inside a raid gets decided in practice rather than on paper.

07

Identity & social

Honor, renown, clans and the name a player carries. Content and system meet in one string.

Lane A — World
  • Honor rank ladder and achievement title content, final naming pass
  • Clan fiction as cave dwellings; hub lore surfaces and the Divide questline seeds
  • Vaelmoor's first outposts — what the raids actually raid
Lane B — Systems
  • Honor and Renown accumulation, permanent win/loss record
  • Clan membership, in-clan item transfer, leadership board and High Warlord standing
  • Market, quests and loadout screens in CommonUI — no in-world NPCs
Gate F Name assembly

Halt both lanes and build one shared assembler for <a>'<b> the <c> of the <d>, including the clanless collapse to the Exiled at the lowest honor rank. One table, one function, used by both the systems that write it and every surface that displays it.

08

Network & performance

A persistent shared world has to hold up with people in it. Lane B owns the network layer; Lane A owns what the streaming and rendering budget will allow.

Lane A — World
  • World Partition streaming budget, HLOD setup, cell load times
  • Nanite and Lumen settings for a lava-lit interior; light bake strategy
  • Actor count and memory budget per cell, agreed with Lane B's numbers
Lane B — Systems
  • Replication pass over combat, inventory and extraction; server authority
  • Relevancy and net update rates; lag compensation on the attack table
  • Persistence for character, grimoire, clan and honor; season reset path
Gate G The budget

Halt both lanes and measure the real zone on a dedicated-server build with a crowd in it: frame time, bandwidth per client, server tick, streaming hitches. Both lanes accept the resulting numbers before either adds more content or more systems.

09

Vertical slice

Both devs, one branch

Lanes close. Everything merges to main and the work is playing the loop until it holds together.

Definition of done

One zone, one raid, the full loop playable on a dedicated server: vent launch, drop-in, fight, find a tome, clear the monument, extract under pressure, rest at home, study, re-equip and go again.

Exit criteria

No lane-local work outstanding, both lane branches deleted, greybox art throughout, and a playtest recording of the loop start to finish. Anything the slice proved wrong goes back into the master design document before new content starts.
